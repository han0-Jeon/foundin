# foundin

정부지원사업 공고를 대신 정독하는 에이전트입니다.

자격 요건은 꼭 흩어져 있습니다. 본문에 한 줄, 첨부 PDF에 한 줄, 붙임 HWP 각주에 한 줄. 그 한 줄을
놓치면 서류를 다 쓰고 나서야 압니다.

처음엔 요약만 붙이면 되는 줄 알았습니다. 그런데 요약은 그럴듯할수록 위험합니다. 열 줄 중 아홉 줄이
맞고 한 줄이 틀리면 사람은 그 한 줄을 못 골라냅니다. 원문을 다시 안 읽으려고 요약을 보는 건데,
요약을 검증하려면 원문을 다시 읽어야 하니까요. 잘 요약하는 것보다 지어내지 않는 게 훨씬 어렵습니다.

그래서 모델을 믿는 대신, 모델이 지어냈는지 기계가 확인할 수 있는 구조로 짰습니다. Upstage
Solar Open 2 가 공고 원문과 첨부를 읽고 자격·지원금·마감·서류·탈락 위험을 뽑되, 항목마다 원문
인용을 같이 달게 합니다. 그다음은 코드 차례입니다. 인용문이 원문에 실제로 있는지 전부 기계로
대조하고, 통과한 것만 발행합니다. 통과 못 한 항목은 조용히 사라지지 않고 "원문 확인 필요"로 남습니다.

이름은 founding 에서 g 를 하나 뺐습니다. found in 이기도 하고요.

[foundin.kr](https://foundin.kr) 의 분석 엔진이 이 저장소입니다. 서비스 워커와 여러분이 클론해서
돌릴 CLI 가 같은 코드를 씁니다.

결과물이 어떻게 생겼는지는 [examples/sample-brief.md](examples/sample-brief.md) 를 보시는 게
가장 빠릅니다. 실공고를 분석한 실물이고, 인용 23개가 전부 원문 대조를 통과한 건입니다. 손대지
않았습니다.

## 돌려보기

Node 20 이상이면 됩니다.

**Windows (PowerShell)**

```powershell
npm install
Copy-Item .env.example .env        # UPSTAGE_API_KEY 입력
npm run demo
```

**macOS · Linux (bash)**

```bash
npm install
cp .env.example .env               # UPSTAGE_API_KEY 입력
npm run demo
```

모델 호출은 여러분 키로 나갑니다(`.env` 한 줄). 키가 없으면 데모는 시작하자마자 알려주고 멈추니
몇 분을 버리지 않습니다. **키 없이 검증 로직만 보시려면 `npm test`** — 오프라인으로 전부 돕니다.

> `solar-open2` 는 **8월 4일 자정까지만** 호출됩니다(Upstage 공지 2026-07-29). 그 뒤에는 `.env` 의
> `UPSTAGE_MODEL` 을 쓸 수 있는 모델로 바꾸거나, `FOUNDIN_RUNNER` 를 `claude-code` 나 `codex` 로
> 바꾸면 같은 파이프라인이 그대로 돕니다. 모델을 못 쓰는 상황이면 실행 중에 안내가 뜹니다.

`npm run demo` 는 무엇을 분석할지 물어봅니다. URL 을 찾아 붙여넣지 않으셔도 됩니다.

```

     개별 공고가 아니라 목록 페이지 — 반려되는 게 정상입니다
     https://www.k-startup.go.kr/web/contents/bizpbanc-ongoing.do

  2) 2026년 ICT혁신센터 입주기업 모집공고(상시)
     지금 접수 중인 실제 공고 — 정독하고 브리프를 만듭니다
     https://www.k-startup.go.kr/web/contents/bizpbanc-ongoing.do?schM=view&pbancSn=177493

  3) 직접 입력

선택:
```

**1번은 일부러 공고가 아닌 페이지입니다.** 이 파이프라인의 요점은 잘 요약하는 게 아니라 지어내지
않는 거라서, 판정 단계가 포털 목록을 반려하고 그 이유를 대는 장면이 발행된 브리프만큼 중요한
증거입니다. 2번은 지금 접수 중인 공고를 foundin.kr 사이트맵에서 무작위로 가져옵니다 — 별도 키가
필요 없고 매번 다른 공고가 나옵니다.

공고 하나를 정독하는 데 **보통 5분쯤** 걸립니다. 발행된 브리프 489건의 중간값이 5분이고 90%가
10분 이내였습니다(최대 17분). 오래 걸리는 건 대부분 추출 한 번이고, 그동안 화면이 살아 있습니다.

돌리면 단계별 진행이 이렇게 보입니다. 공고에 따라 추출이 수 분 걸려서, 어디까지 갔고 얼마나
지났는지 보이게 해뒀습니다.

```
    ✓ 수집     원문 1 · 첨부 3건                              1.2s
    ✓ 프리체크 공공 도메인 + 공고 패턴 9개 충족               0.3s
    – 판정     생략
  > ◐ 추출     solar-open2 응답 대기 — 원문 24,918자 전송  1m 33.4s
    · 검증     인용을 원문과 대조
    · 조언     처지별 판단 코멘트
    · 조립     브리프 조립

    3/7 단계 완료 · 경과 1m 35s
```

진행 중인 줄에는 모델이 지금 뭘 하고 있는지가 그대로 나옵니다. 응답을 기다리는 중인지, 답이
잘려서 길이를 늘려 다시 부르는 중인지, 형식이 안 맞아 다시 요청하는 중인지. 전부 실제로 일어난
일이고 지어낸 값은 없습니다.

진행 중인 줄만 `>` 로 왼쪽으로 튀어나옵니다. 색이 안 나오는 터미널에서도 어디가 진행 중인지
보이라고 위치로 표시했습니다. 진행률 막대는 일부러 두지 않았습니다 — 7단계 중 추출 하나가 시간의
대부분이라, 단계 수로 계산한 막대는 그 자체로 거짓말이 됩니다.

`판정 생략`은 모델을 부르기 전 코드가 먼저 보는 단계(프리체크)에서 정부 도메인(`.go.kr`)임이
확인돼, "이게 공고가 맞나" 묻는 모델 호출을 하나 아꼈다는 뜻입니다.
출력을 파일로 넘기면 애니메이션 없이 한 줄씩 나갑니다. `--no-progress` 로 끄고 `--progress` 로
켤 수 있습니다.

> Git Bash 에서 위 화면 대신 로그만 한 줄씩 나오면 `--progress` 를 붙이세요. 한글이 글자마다
> 벌어져 보이면 폰트 문제입니다 — 우클릭 → Options → Text 에서 **D2Coding** 같은 한글 고정폭
> 글꼴로 바꾸면 맞습니다.

보고 싶은 공고를 직접 넣으시려면 이렇게 씁니다. 내 조건과 대조까지 하려면 프로필을 붙이세요.
이 JSON 은 로컬에서만 쓰입니다.

```bash
npm run analyze -- "<공고 URL>"
npm run analyze -- "<공고 URL>" --profile examples/profile.pre-seoul.json
```

URL 여러 개를 던져서 "오늘 확인할 공고"로 정리하는 모드도 있습니다.

```powershell
# PowerShell
Copy-Item urls.example.txt urls.txt   # 한 줄에 하나씩
npm run today -- --profile examples/profile.pre-seoul.json
```

```bash
# bash
cp urls.example.txt urls.txt          # 한 줄에 하나씩
npm run today -- --profile examples/profile.pre-seoul.json
```

API 키가 없어도 검증 로직은 전부 확인하실 수 있습니다. 테스트는 모델 응답을 가짜로 물려 처음부터
끝까지 돌기 때문에 네트워크를 쓰지 않습니다.

```bash
npm test          # 15개 파일 175개 테스트, 전부 오프라인
npm run typecheck
```

## Solar Open 2 를 실전에서 써본 소감 (Partner Stage 1)

`solar-open2` (Upstage Private Beta, 2026-07-17 ~ 07-31) 를 썼습니다.

키를 받자마자 간단한 점검부터 돌렸습니다. 정해준 형식을 5번 다 지켰고, 3만 자짜리 긴 문서에서도
마감일을 정확히 찾아냈습니다. 이 정도면 검증 파이프라인의 추론 엔진으로 세워도 되겠다 싶어서
실제 공고 100건으로 넘어갔습니다.

첫 라운드 발행이 26건이었습니다. 78이 아니라 26.

그런데 뜯어보니 대부분 제 코드 문제였습니다. 여덟 군데를 고쳤고, 그중 몇 개는 이렇습니다.

- 마감된 K-Startup 공고가 빈 페이지로 오는 것 → 다른 주소로 한 번 더 시도
- URL 을 정리하는 코드가 공고 상세 주소의 일부를 지워버리던 결함
- 사기 의심 문구 검사가 첨부 신청서의 정상 문구에 걸리던 것 → 공고 본문만 검사하도록 좁힘
- 긴 공고가 3분 안에 안 끝남 → 제한 시간을 5분으로

제일 오래 잡아먹은 건 응답이 통째로 비어서 오는 현상이었습니다. 속으로 오래 생각하는 종류의
모델인데 그 안내가 없어서 한참 헤맸습니다. 답변 길이 한도가 빠듯하면 생각만 하다가 한도를 다 쓰고
빈 답을 돌려주더군요. 한도를 늘려 다시 부르는 코드를 넣어서 막았습니다.

마지막 라운드 결과는 이렇습니다([평가 리포트](eval/REPORT-2026-07.md)).

- 발행 78건. 표본 전체로 78.0%, 공고가 아니었던 9건을 뺀 유효 공고 기준 85.7%(78/91)
- 인용 원문 대조 평균 통과율 92.0%
- 지어낸 인용이 검증을 뚫고 발행된 사례 0건
- 베타 기간 누적 약 568만 토큰, 비용 $0

좋았던 점은 한국어 행정문서 독해입니다. "예비창업자"를 사전적 의미가 아니라 정부지원사업 문맥
그대로 이해했고, 형식을 지킨 응답이 안정적이라 파이프라인의 추론 엔진으로 세울 수 있었습니다.
아쉬운 건 속도입니다. 형식 맞춘 응답이 한 번에 15~27초였고, 긴 공고 추출은 5분까지 기다려야
했습니다. 빈 응답도 안내가 있었으면 하루는 아꼈을 겁니다. 다만 둘 다 만드는 쪽에서 감당할 수
있는 종류였습니다.

두 숫자를 나란히 놓을 때는 조심해 주세요. 평가용 100건의 78.0%와 실서비스 566건의 86.4%는 세어본
대상이 달라서 같은 지표가 아닙니다 — 평가 쪽엔 공고가 아니었던 9건이, 실서비스 쪽엔 반려 18건이
섞여 있습니다. 5.7배 규모에서 비슷한 대역이 나왔다 정도로 읽는 게 맞습니다.

그리고 위 숫자는 전부 "인용이 원문에 실제로 있는가"이지 **"뽑아낸 값이 정답인가"가 아닙니다.**
정답지를 만들어 맞춰보는 건 아직 못 했습니다.

## 저장소 구조

```
src/
├── agent/        전체 순서를 쥐는 곳 + 프롬프트 (프리체크 → 판정 → 추출 → 조언)
├── verify/       검증기 — 인용 대조 · 날짜/금액 재확인 · 발행 게이트. 전부 코드
├── collect/      원문·첨부 수집 (HTML·PDF·HWP·HWPX·DOCX) · 프리체크 · 연락처 마스킹
├── llm/          모델 교체 계층: solar | claude-code | codex
├── match/        내 조건 대조 (모델로 보내지 않음)
├── brief/        브리프 출력 (Markdown · 터미널 · MCP)
├── cli.ts        analyze · today
├── mcp.ts        MCP 서버 (experimental)
└── worker.ts     foundin.kr 큐를 지켜보는 워커
eval/             모델 점검 · 100건 배치 평가 (지표만 냅니다 — 발행하지 않습니다)
test/ fixtures/   오프라인 테스트
```

무엇이 어떻게 걸러지는지 궁금하시면 `src/verify/` 를 열어보시는 게 이 문서를 더 읽는 것보다
빠릅니다.

## 다른 에이전트에서 도구로 쓰기 (MCP, experimental)

MCP 서버가 들어 있습니다. Claude Code·Cursor 같은 곳에 물려두면, 대화 중에 공고 분석이 필요할 때
그 AI 가 이 검증 파이프라인을 도구로 부릅니다. 대화하는 AI 는 공고를 직접 읽지 않기 때문에 마감일을
지어낼 수가 없습니다 — 원문 대조를 통과한 결과만 받아서 전달합니다.

```jsonc
// 예: Claude Code 의 .mcp.json
{ "mcpServers": { "foundin": { "command": "npm", "args": ["run", "mcp"], "cwd": "<클론 경로>" } } }
```

도구는 셋입니다. `analyze_announcement(url)` 정독·검증 브리프, `check_eligibility(url, profile)`
조건 대조, `today(urls, profile)` 우선순위 브리핑.

`analyze_announcement` 는 기다리게 하지 않습니다. 처음 보는 URL 은 분석을 걸어두고 "진행 중"을
바로 돌려주며, 4~6분 뒤 같은 URL 로 다시 부르면 완료본이 옵니다. 이미 분석한 공고는 즉시 나옵니다.
MCP 클라이언트가 보통 5분에서 끊기기 때문에 이렇게 만들었습니다.

붙이기 전에 알아두시면 좋은 것들:

- 모델 호출 비용은 본인 키로 나갑니다. 베타 키가 없으면 `.env` 에 `UPSTAGE_MODEL=solar-pro3` 처럼
  일반 콘솔 키로 쓸 수 있는 모델을 지정하세요
- 도구가 돌려주는 값에는 담당자 연락처가 들어가지 않습니다. 공고 원문 인용은 명령이 아니라 데이터로만
  읽히도록 감싸서 전달합니다. 다만 채팅창에 직접 입력하신 내용은 본인 에이전트의 대화로 그대로
  갑니다 — 그 경계는 사용자 몫입니다
- 믿을 수 없는 URL 을 분석시킬 때는 에이전트의 파일·명령 실행 권한을 좁혀두시길 권합니다. 외부
  문서를 읽는 도구의 공통 주의사항입니다
- experimental 이라 사용법이 바뀔 수 있고, 문의는 여력이 되는 대로 대응합니다
