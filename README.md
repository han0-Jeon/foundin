# foundin

정부지원사업 공고를 대신 정독하는 에이전트입니다.

자격 요건은 꼭 흩어져 있습니다. 본문에 한 줄, 첨부 PDF에 한 줄, 붙임 HWP 각주에 한 줄. 그 한 줄을
놓치면 서류를 다 쓰고 나서야 압니다.

처음엔 요약만 붙이면 되는 줄 알았습니다. 그런데 요약은 잘 될수록 확인하기 어려워집니다. 열 줄 중
아홉 줄이 맞고 한 줄이 다르면 사람은 그 한 줄을 골라내지 못합니다. 원문을 다시 안 읽으려고 요약을
보는 건데, 요약이 맞는지 보려면 결국 원문을 다시 읽어야 하니까요.

그래서 요약에 **근거**를 같이 받기로 했습니다. Upstage Solar 가 공고 원문과 첨부를 읽고
자격·지원금·마감·서류·탈락 위험을 뽑되, 항목마다 그 근거가 된 원문 문장을 함께 답니다. 그리고 그 문장이 원문에 실제로 있는지 전부 대조하고, 통과한 것만 발행합니다. 
통과하지 못한 항목은 조용히 사라지지 않고 "원문 확인 필요"로 남습니다.


[foundin.kr](https://foundin.kr) 의 분석 엔진이 이 저장소입니다. 

결과물이 어떻게 생겼는지는 [examples/sample-brief.md](examples/sample-brief.md) 를 보시는 게
가장 빠릅니다. 실공고를 분석한 실물이고, 인용 23개가 전부 원문 대조를 통과한 건입니다.

## 돌려보기

Node 20 이상.

**Windows (PowerShell)**

```powershell
npm install
Copy-Item .env.example .env        # UPSTAGE_API_KEY 입력
npm run demo
```

**macOS · Linux (bash)**

```bash
npm install
cp .env.example .env               # UPSTAGE_API_KEY 입력
npm run demo
```

모델 호출은 개인 API 키로 나갑니다(`.env` 한 줄). 키가 없으면 데모는 시작하자마자 알려주고 멈춥니다.
**키 없이 검증 로직만 보시려면 `npm test`** — 오프라인으로 전부 돕니다.

> 기본 모델은 `solar-pro4` 입니다 (구 `solar-open2` 는 2026-08-04 자정에 종료). 무료 체험이
> 끝나 모델을 못 쓰게 되면, `.env` 의 `UPSTAGE_MODEL` 을 쓸 수 있는 모델로 바꾸거나
> `FOUNDIN_RUNNER` 를 `claude-code` 나 `codex` 로 바꾸면 같은 파이프라인이 그대로 돕니다.
> 모델을 못 쓰는 상황이면 실행 중에 안내가 뜹니다.

아래는 `npm run demo` 예시입니다.

```
무엇을 분석할까요?

  1) K-Startup 사업공고 목록
     개별 공고가 아니라 목록 페이지 — 반려되는 게 정상입니다
     https://www.k-startup.go.kr/web/contents/bizpbanc-ongoing.do

  2) 2026년 ICT혁신센터 입주기업 모집공고(상시)
     지금 접수 중인 실제 공고 — 정독하고 브리프를 만듭니다
     https://www.k-startup.go.kr/web/contents/bizpbanc-ongoing.do?schM=view&pbancSn=177493

  3) 직접 입력

선택:
```

**1번은 공고가 아닌 페이지입니다.** 이 파이프라인의 요점은 잘 요약하는 게 아니라 근거 없는
값을 내보내지 않는 것이라, 판정 단계가 포털 목록을 반려하고 그 이유를 대는 장면이 발행된 요약만큼
중요한 증거입니다. 2번은 지금 접수 중인 공고를 foundin.kr 사이트맵에서 무작위로 가져옵니다.

공고 하나를 정독하는 데 **보통 5분쯤** 걸립니다. 발행된 요약 489건의 중간값이 5분이고 90%가
10분 이내였습니다(최대 17분). 오래 걸리는 건 대부분 추출 부분 이었습니다.

공고에 따라 추출이 수 분 걸려서, 어디까지 갔고 얼마나 지났는지 보이게 해뒀습니다.

```
    ✓ 수집     원문 1 · 첨부 3건                              1.2s
    ✓ 프리체크 공공 도메인 + 공고 패턴 9개 충족               0.3s
    – 판정     생략
  > ◐ 추출     solar-pro4 응답 대기 — 원문 24,918자 전송   1m 33.4s
    · 검증     인용을 원문과 대조
    · 조언     처지별 판단 코멘트
    · 조립     브리프 조립

    3/7 단계 완료 · 경과 1m 35s
```


`판정 생략`은 모델을 부르기 전 코드단에서 정부 도메인(`.go.kr`)임이
확인돼, "이게 공고가 맞는지" 묻는 모델 호출을 하나 아꼈다는 뜻입니다.

> Git Bash 에서 위 화면 대신 로그만 한 줄씩 나오면 `--progress` 를 붙이세요.

보고 싶은 공고를 직접 넣으시려면 이렇게 씁니다. 

```bash
npm run analyze -- "<공고 URL>"
```


API 키가 없어도 검증 로직은 전부 확인하실 수 있습니다. 테스트는 모델 응답을 가짜로 물려 처음부터
끝까지 돌기 때문에 네트워크를 쓰지 않습니다.

```bash
npm test          # 16개 파일 186개 테스트, 전부 오프라인
npm run typecheck
```

## Solar Open 2 를 사용해 본 소감 (Partner Stage 1)

`solar-open2` (Upstage Private Beta, 2026-07-17 ~ 07-31)

키를 받자마자 간단한 점검부터 돌렸습니다. 정해준 형식을 5번 다 지켰고, 3만 자짜리 긴 문서에서도
마감일을 정확히 찾아냈습니다. 이 정도면 검증 파이프라인의 추론 엔진으로 세워도 되겠다 싶어서
실제 공고 100건으로 넘어갔습니다.

첫 라운드 발행이 26건이었습니다.

그런데 뜯어보니 대부분 제 코드 문제였습니다. 여덟 군데를 고쳤고, 그중 몇 개는 이렇습니다.

- 마감된 K-Startup 공고가 빈 페이지로 오는 것 → 다른 주소로 한 번 더 시도
- URL 을 정리하는 코드가 공고 상세 주소의 일부를 지워버리던 결함
- 사기 의심 문구 검사가 첨부 신청서의 정상 문구에 걸리던 것 → 공고 본문만 검사하도록 좁힘
- 긴 공고가 3분 안에 안 끝남 → 제한 시간을 5분으로

마지막 라운드 결과는 이렇습니다([평가 리포트](eval/REPORT-2026-07.md)).

- 발행 78건. 표본 전체로 78.0%, 공고가 아니었던 9건을 뺀 유효 공고 기준 85.7%(78/91)
- 인용 원문 대조 평균 통과율 92.0%
- 원문에 없는 인용이 검증을 뚫고 발행된 사례 0건
- 베타 기간 누적 약 568만 토큰

좋았던 점은 **한국어 행정문서 독해**입니다. "예비창업자"를 사전적 의미가 아니라 정부지원사업 문맥
그대로 이해했고, 형식을 지킨 응답이 안정적이라 파이프라인의 추론 엔진으로 세울 수 있었습니다.
아쉬운 건 속도입니다. 형식 맞춘 응답이 한 번에 15~27초였고, 긴 공고 추출은 5분까지 기다려야
했습니다.


## 다른 에이전트에서 도구로 쓰기 (MCP, experimental)

MCP 서버가 들어 있습니다. Claude Code·Cursor 같은 곳에 물려두면, 대화 중에 공고 분석이 필요할 때
그 AI 가 이 검증 파이프라인을 도구로 부릅니다. 원문 대조를 통과한 결과만 받아서 전달합니다.

```jsonc
// 예: Claude Code 의 .mcp.json
{ "mcpServers": { "foundin": { "command": "npm", "args": ["run", "mcp"], "cwd": "<클론 경로>" } } }
```

도구는 셋입니다. `analyze_announcement(url)` 정독·검증 브리프, `check_eligibility(url, profile)`
조건 대조, `today(urls, profile)` 우선순위 브리핑.

`analyze_announcement` 는 기다리게 하지 않습니다. 처음 보는 URL 은 분석을 걸어두고 "진행 중"을
바로 돌려주며, 4~6분 뒤 같은 URL 로 다시 부르면 완료본이 옵니다. 이미 분석한 공고는 즉시 나옵니다.
MCP 클라이언트가 보통 5분에서 끊기기 때문에 이렇게 만들었습니다.

붙이기 전에 알아두시면 좋은 것들:

- 모델 호출 비용은 본인 키로 나갑니다. 베타 키가 없으면 `.env` 에 `UPSTAGE_MODEL=solar-pro3` 처럼
  일반 콘솔 키로 쓸 수 있는 모델을 지정하세요
- 도구가 돌려주는 값에는 담당자 연락처가 들어가지 않습니다. 공고 원문 인용은 명령이 아니라 데이터로만
  읽히도록 감싸서 전달합니다. 다만 채팅창에 직접 입력하신 내용은 본인 에이전트의 대화로 그대로
  갑니다 — 그 경계는 사용자 몫입니다
- 믿을 수 없는 URL 을 분석시킬 때는 에이전트의 파일·명령 실행 권한을 좁혀두시길 권합니다. 외부
  문서를 읽는 도구의 공통 주의사항입니다
- experimental 이라 사용법이 바뀔 수 있고, 문의는 여력이 되는 대로 대응합니다
